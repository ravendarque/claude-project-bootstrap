# Security policy

## Reporting a vulnerability

Please report security vulnerabilities privately, not in a public issue.

Use GitHub's private vulnerability reporting: the "Report a vulnerability"
button on this repository's
[Security tab]({{repo_url}}/security/advisories/new). It opens a private
draft advisory that only the maintainers can see until a fix is ready.

Please include:

- a description of the vulnerability and its impact;
- steps to reproduce, with a minimal proof of concept where possible;
- a suggested fix, if you have one.

## What to expect

Responses are best effort. We aim to acknowledge a report within 7 days and
keep you updated. Confirmed vulnerabilities are fixed and disclosed through
a GitHub Security Advisory once a fix is available.

## Good-faith research

If you look for vulnerabilities in good faith and follow this policy, we
won't take action against you, and we'll work with you to understand and fix
what you find. Please:

- only use accounts you own, or that you've made for testing;
- never access, change or keep another person's data. If you come across
  some, stop and tell us;
- don't run denial-of-service or high-volume tests;
- don't use social engineering, phishing or physical attacks;
- give us a reasonable chance to fix a problem before you talk about it
  publicly.

## Supported versions

Only the latest release (the most recent `vX.Y.Z` tag) is supported. Fixes
are not backported.
